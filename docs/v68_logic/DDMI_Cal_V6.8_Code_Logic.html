1. The big picture

The run has three layers:

  1. MES wrapper — Cimes_Interface.vi (the real top level): checks the module in, downloads the limits, starts the test VI, uploads the result and checks the module out.
  2. Test state machine — 800G_TRx_Test.vi: a while loop around a case structure; each case is a named state (enum Main_Step), and a queue (array) of states decides what runs next.
  3. Worker VIs: 800G SIP Tx MPD Monitor.vi (MPD scan), Item_Test.vi (Adjust Power, Scan_Disable, DDMI_Adjust_TX, DDMI_RXP, DDMI_VCC, DDMI_Temp), DDMI_Cal.vi (the TX / RX / VCC / temperature calibration maths and register writes), Auto Adjust Vcc.vi, Peak Search.vi, and IIC.vi (every module register access, by command enum).
MES Pcs_Check_IN -> Read_Date -> Read_Spec -> Read_Test_Times -> (TOOL) | State Reini -> Set_Temp -> Read SN -> Read_Spec -> Wait_Temp -> VCC -> StartTest | StartTest queues: Scan_MPD -> DDMI_CAL -> ShowPF -> Move_out -> Stop | Scan_MPD (outer loop, up to 2 passes; stops when Scan_Disable passes) |- MPD Monitor scan (inner loop, up to 2 scans; stops when the scan passes) |- Adjust Power (first pass only, and only if Only_Test = False) '- Scan_Disable (TX-disable tuning, all lanes together) DDMI_CAL DDMI_Adjust_TX -> DDMI_RXP -> DDMI_VCC -> DDMI_Temp (each item: calibrate + check, re-run once if its check fails) ShowPF temp-offset off, exit test mode, reset, DSP-mode check, PASS/FAIL | MES Save_Data -> Pcs_Check_OUT (only if Save_Data succeeded)

Typical time. The production time study (800G AWS 2FR4&DR8+ DDMI和TP2&3調整邏輯) gives 568 s of program time for two modules, 5 min 19 s per module including about 35 s of manual handling. Most of the time is I²C access (IIC.vi waits 500 ms after a page switch for many reads), not the fixed waits.

4. Start-up states

4.1 Reini

  • Opens the attenuator units (2×FR4: one AT4208, channel 1 → RX1 = CH1–4, channel 2 → RX2 = CH5–8) and sets them to 1.0 dB.
  • DCA initialisation only if configured (not used at DDMI Cal).
  • No module reset for AWS at DDMI Cal; W_TestMode = 0 + W_Reset run here only for FQC / Final test.

4.2 Set_Temp

  • Station DDMI CAL, customer AWS: W_AWS_Test_Mode = 0 (EEh:80h). [HW] With 1 the module accepts but ignores IBias writes and freezes disabled lanes; with 0 both work.
  • V6.8 has no temperature controller at DDMI Cal: no temperature is set.

4.3 Read SN

  • R_Information 00h:94h, 34 bytes ASCII: PN = bytes 148–163, revision 164–165, SN 166–181.
  • Must equal the scanned SN, otherwise "Inconsistent internal and external SN" → FAIL, stop.

4.4 VCC

Auto Adjust Vcc.vi: the module reading (I2C Read Vcc) must be 2.8–4.0 V; first setting = supply output + half the error; then set, wait 2000 ms, measure the voltage at the module, add half the error to the setting; repeat until within 0.01 V of 3.3 V (stop if a setting would exceed 4.0 V). The supply is switched on by the operator, not by the program. Current limit parameter 6000 mA. Then the module current is read and must exceed the value in ICC Spec.txt (1.8 A) or the test ends. [HW] The module's own VCC monitor lags a supply change by seconds; the 2 s wait is needed.

4.5 Read_Spec and Wait_Temp

  • Read_Spec here only shows the limits (the wrapper already downloaded them).
  • Wait_Temp is skipped at the DDMI Cal station (the frame compares the station with "DDMI Cal"). For other stations it waits for the case temperature from a thermostream (RT AWS window 30–40 °C, ATS LT −5, ATS HT 70 °C …).

5. Scan_MPD state

Purpose: find each lane's operating point on its modulator (MZM) curve, teach the firmware TOPS loop to hold it, set the laser bias, and tune the TX-disable voltage.

for pass in 1..2: outer loop; stop when Scan_Disable passes for scan in 1..2: inner loop; stop when the scan passes 800G SIP Tx MPD Monitor.vi (frames 0..5 below) if pass == 1 and not Only_Test: Item_Test "Adjust Power" Item_Test "Scan_Disable"

The Adjust Power case is selected by the outer loop counter (case 0 runs it) and sits inside a case on the global Only_Test (False → run). In a normal production run Only_Test is False.

5.3 The analysis (frame 2)

  1. Peak Search.vi (peaks and valleys): mean threshold; one entry per run of points above/below it; a peak run starting at sweep point 0 is not reported.
  2. Pairing: peak k with valley k; kept when peak index − valley index > 1, valley index ≥ 5 (AWS) and peak index < (Max − Min) / Step. AWS then takes the kept pair with the deepest valley (Array Max & Min, min index). The result is a rising edge (Vtops_Mid > Vtops_min, change list 2025-10-09). [HW] On a falling edge the firmware loop does not hold the lane after a reset.
  3. Target levels: (1 − x) × peak for x in [0.65, 0.56, 0.50, 0.44] = 4.5 / 3.5 / 3.0 / 2.5 dB below the peak.
  4. Closest step between the chosen valley and peak (no interpolation). If the 3.5 dB and 3.0 dB points share a step, the 3.5 dB point moves one step lower.
  5. Tops_Mid = mean of the 3.5 dB and 3.0 dB voltages; Tops_setpoint = round(TXMON ÷ MPD_OUT × 1000) at Tops_Mid.

5.4 Adjust Power (Item_Test.vi, AWS LC-2*FR4)

  1. Write the default bias setpoint [280, 280, 410, 450] (one value per laser) to all three registers: W_Bias_setpoint (RT, E9h:D2h), W_Bias_setpointHT (E9h:B0h), W_Bias_setpointLT (E9h:B8h) — IIC.vi commands 55/56/57.
  2. Wait 2 s, read the 8 true TX powers (meter + Tx Loss).
  3. Per laser n: mean of the dBm powers of CH n and CH n+4 (Mean.vi). Below 0.7 dBm → +20; above 2.3 dBm → −30; otherwise unchanged. One step only.
  4. If anything changed, write the new values to RT, HT and LT.

The second AWS branch ([300, 350], window 1.0–2.6 dBm, 2 lasers) is the MPO-DR8 case. The final power adjustment (up to 5 steps, 150–750) is done later at the TP2/TP3 station.

A module that has already passed TP2/TP3 and is re-run through DDMI Cal gets its bias setpoints reset to these defaults: its supply current and TX power drop (seen on hardware: about 150 mA less).

5.5 Scan_Disable (Item_Test.vi): TX-disable tuning

All 8 lanes are handled together: W_TXDis (10h:82h) is written with IIC.vi "channel 9" (0xFF, all lanes off) and "channel 8" (0x00, all lanes on), and the 8-channel meter reads all lanes at once.

  1. Start from each lane's tops_off (the scan's valley). Measure at tops_off, tops_off + 0.01 V, tops_off − 0.01 V.
  2. For each lane, step 0.01 V four more times in the direction that got darker; keep the darkest voltage.
  3. Write the best tops_off, disable, wait 0.1 s, read the leakage; enable, wait 1 s.
  4. If a lane is still above −18 dBm, five more steps in its direction (this block is in V6.8; change list V6.5).
  5. Every step writes tops_off and re-toggles the lanes (enable all, disable all): the module applies tops_off when a lane is disabled. [HW] A tops_off write to a lane that stays disabled has no effect.
  6. Result: Tx_Disable(dBm), Tops_Mid, Tops_off per lane; limit −60 to −16 dBm (−18 dBm is only the tuning trigger).

Waits inside the loop are 0 s and 0.01 s; the I²C and meter reads take most of the time. All W_Reset blocks in Scan_Disable belong to the MPO-DR8 case and are commented out.

6. DDMI_CAL state

For each item (DDMI_Adjust_TX, DDMI_RXP, DDMI_VCC, DDMI_Temp) Item_Test.vi calls DDMI_Cal.vi with Select = Cal, then Select = Check, in a while loop that re-runs once (50 ms wait) when the check fails: TX if slope outside 5–150 or |dTxP| > 0.5 dB; RX if slope outside 5–30 or |dRxP| > 0.5 dB.

The common fit (Calulate_Curve Fit Coefficient.vi, linear): two known true values y and the module's raw readings x → slope = (y₂ − y₁) ÷ (x₂ − x₁), offset = y₁ − slope × x₁. The module reports y = slope × raw + offset itself. Units are linear: power in mW × 10000 (0.1 µW), voltage in V × 10000 (100 µV).

6.2 RX power calibration (frame "Rxp", Cal)

  1. For −2 dBm and then −10 dBm, look up each lane's attenuation in its RX table (CH RxP To Att.vi, linear interpolation).
  2. 2×FR4 works in lane pairs (1,5), (2,6), (3,7), (4,8) ("2XFR4 two CH Parallel"): set the pair's wavelength and attenuation on both attenuator channels, read R_RSSI F3h:A6h (8 × U16, little-endian), keep the two active lanes.
  3. Per lane: y = −2 dBm → 6310, −10 dBm → 1000; x = RSSI → slope, offset; write W_DRXPCal (ECh/EDh, 90h).
  4. Wait after each pair: "ATT Delay(s)" ("BERT Time" station setting) + 2 s. Fit input y = 10^(dBm/10) × 10000, not rounded.
  5. Check (Item_Test.vi DDMI_RXP; DDMI_Cal's Rxp "Check" case is empty): −6 dBm in the same pairs, read R_DRXP 11h:BAh, error = DDMI − (−6), |error| < 0.5 dB and RX slope 5–30, else Cal + Check once more.

6.4 Temperature (frame "Temp")

Read R_DTEMP 00h:0Eh, signed 16-bit ÷ 256 = °C. Limit 30–60 °C. No temperature calibration at DDMI Cal (the 500-read offset routine with W_TempCalRT/HT/LT exists in the VI but is not used here).

15.1 Peak Search.vi (used by the MPD scan analysis)

  1. Threshold = mean of the whole sweep (sum ÷ number of points).
  2. The curve is walked point by point. A valley region is a run of points below the mean and a peak region is a run at or above it.
  3. Inside each region the lowest value (valleys) or highest value (peaks) is tracked with its index. When the curve crosses the mean, or the sweep ends, that value and index are appended.
  4. Outputs: Amplitude[], Location[] and Found (the count). The MPD Monitor calls it once for "Peaks" and once for "Valleys".

Pairing in 800G SIP Tx MPD Monitor.vi: peak k is paired with valley k (same index). The pair is used only when peak index − valley index > 1 (a distance in sweep points), the valley index is at least 5 for AWS (20 or 100 for other customers), and the peak index is below (Vtops_Max − Vtops_Min) / Step. AWS then takes the kept pair with the deepest valley. With the valley-index rule our edge choice matched the LabVIEW-stored operating point on 7 of 8 lanes of P172262504894 (CH6 differs). Python: MIN_VALLEY_INDEX = 5 in ddmi/calc/tops.py.

15.5 RX table lookup (CH RxP To Att.vi, Read ATT Table_400G.vi, Calulate_Curve Fit Coefficient.vi)

  1. CH RxP To Att.vi picks the table by channel. Case 0–3 use the globals CH1 Cal … CH4 Cal (the text of CHn_Rx_calibration.txt).
  2. Read ATT Table_400G.vi turns the text into a 2-column array (column 0 attenuation, column 1 power). Rx Pow→Att: (target + RxP Offset) is looked up in the power column with linear interpolation, giving the attenuation. Att→Rx Pow: the reverse, minus the RxP Offset.
  3. Calulate_Curve Fit Coefficient.vi fits y against x: curve type 0 = Linear (a0 + a1·x), others = polynomial up to a4. It returns the coefficients, the fitted curve and the MSE. For DDMI_CAL the two-point linear case gives slope and offset (section 13).

15.6 Wait_Temp.vi (skipped at DDMI Cal)

The VI polls the module temperature (IIC R_DTEMP, or an IR thermometer / thermostream when one is selected) once every 1000 ms. It keeps the last 30 readings and is stable when their max − min is inside the window. For the "Final test HT" stations it also compares against 49 °C. A disabled frame holds an old thermostream set-point of 43.5 °C. It does not run at DDMI Cal, where the state is skipped.

15.7 Display (Dispaly.vi)

This is a front-panel helper. It calls Check light, Check if File or Folder Exists and Analysis error, and it fills the result display. It writes no module registers.
