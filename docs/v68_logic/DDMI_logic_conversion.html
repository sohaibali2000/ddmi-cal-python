Time budget

Production: 568 s of program time for two modules, about 5 min 19 s per module including about 35 s of handling. Fixed waits add up to only about 50–60 s per module. The rest is I²C: IIC.vi waits 500 ms after each page switch on many reads (R_RSSI, R_DRXP…R_IBias, R_Bias_setpoint…R_tops setpoint). This was raised from 75 ms in 2025-09. Python now waits the same per command (section 13), so a run takes about as long as V6.8's; it waits longer only in the sweep and Scan_Disable, where this station needs it.

Auto Adjust Vcc.vi (automatic mode)

  1. Read the module voltage (I2C Read Vcc.vi + Vcc Offset). It must be 2.8–4.0 V, otherwise "Please check your Multimeter".
  2. First setting = present supply output (PS Read Volt.vi) + (target − module) ÷ 2. It must be below 4.0 V.
  3. Loop: set the supply (PS Set V & A, 6000 mA), wait 2000 ms, read the module voltage. Done when |target − module| < 0.01 V. Otherwise setting += (target − module) ÷ 2 (half-step correction). Stop with a failure if the next setting is above 4.0 V.
  4. Drop VCC = supply output − module voltage is shown on screen. Times = number of loops.

With about 0.3 V of cable drop, the half-step needs about 5 loops (about 10 s) per voltage. The same VI is used for the VCC cal points (section 7).

Limits / failures

  • SN mismatch → "Inconsistent internal and external SN" → FAIL, stop.
  • Module voltage outside 2.8–4.0 V → "Please check your Multimeter".
  • Adjust fails → "VCC voltage regulation failed".
  • ICC not above 1.8 A → "Current x.xxA failed" (module not drawing power or not seated).
Why AWS_Test_Mode must be 0 HW: with 1, the module acknowledges IBias writes but ignores them, and it freezes disabled lanes. TX Cal and Scan_Disable then fail. This was the root cause of the early failing runs.
V6.8 vs Python (aligned 2026-10-19: order, half-step adjust, 2.8–4.0 V pre-check, 4.0 V cap, 6000 mA limit, ICC strictly above 1.8 A, same messages)
  • PY Before the first write, Python reads every register the run will change and saves it to results/backups/<SN>_<time>_backup.json. Restore it with python -m ddmi restore --file …. Read-only.
  • PY Python reads the PN before MES Read_Spec, so MES returns the limits for this product.
  • PY Extra adjust guards: at most 20 loops (V6.8 has no count limit), never more than 0.5 V above the target, and the supply driver's own station limit (3.9 V).
  • PY The current limit is sent once per adjust. V6.8 sends it with every voltage, but the value never changes.
  • PY Reini also sets the TX meter wavelengths (1270/1290/1310/1330 nm × 2) and its averaging (100 ms). The LX meter needs them.
  • Reini uses 1.0 dB, or the station's minimum attenuation if that is higher (receiver protection on this bench).
  • Python's wait_temp exists but is disabled (enabled: false), matching V6.8.

The module's own VCC monitor lags a supply change by seconds HW, so the 2 s wait is required. With 0.2 s, the VCC cal read the previous point.

Analysis: Peak Search and pairing (frame 2)

  1. Peak Search.vi, run once for valleys and once for peaks. Threshold = mean of the whole sweep. Each run of points at or below the mean gives one valley (its lowest point), and each run at or above it gives one peak (its highest point). The first point wins a tie, and a run still open at the sweep end counts. A peak run that starts at sweep point 0 is not reported (the VI's run flag starts FALSE for peaks and TRUE for valleys). That is why a sweep starting high still pairs each valley with the peak after it.
  2. Pairing loop: peak k with valley k. A pair is kept when all three hold:
    • peak index − valley index > 1 (a distance in sweep points: the peak comes after the valley, i.e. a rising edge);
    • valley index ≥ 5 (AWS; default 20, Acacia 100);
    • peak index < (Vtops_Max − Vtops_Min) ÷ Step = 125 (the peak is not the last sweep point).
  3. Which pair: AWS uses the default case, Array Max & Min on the kept valley amplitudes, min index, i.e. the pair with the deepest valley. Acacia takes the highest peak instead.
  4. Target levels: constant [0.65, 0.56, 0.50, 0.44] used as (1 − x) × peak:
    ConstantLeveldB below peakUsed for
    0.6535 % of peak4.5 dBTXP_MPDOut_4.5dB
    0.5644 % of peak3.5 dBTXP_MPDOut_3.5dB, Tops_Mid
    0.5050 % of peak3.0 dBTXP_MPDOut_3dB, Tops_Mid
    0.4456 % of peak2.5 dBTXP_MPDOut_2.5dB
  5. Closest step on the edge: for each level, the sweep step between the chosen valley and peak whose TXMON is closest (Array Subset, |difference|, min index). No interpolation.
  6. Same-step rule: if the 3.5 dB and 3.0 dB points land on the same step, the 3.5 dB point is set one step lower.
  7. Tops_Mid = mean of the 3.5 dB and 3.0 dB voltages (inserted as the 5th point).
  8. Tops_setpoint = round(TXMON ÷ MPD_OUT × 1000) at Tops_Mid (typical 500–900). TXP_MPDOut_x = the same ratio at the 4 levels (record only).
Checked on a real module (P172262504894, our sweep vs the tops_off the LabVIEW station left): the chosen valley matches on 6 of 8 lanes within 0.05 V. CH3 and CH6 each have two valleys of equal depth (13 vs 14 and 10 vs 10 counts), so "deepest valley" depends on sweep noise. LabVIEW's sweep picked the other one. The old Python rule (first valley) matched 7 of 8 by chance but not by the same logic.

The sweep values are also converted to volts (/4096 × 2.5) for the charts and the Delta / Vavg displays. Peak Search, pairing and the closest-step search do not depend on that scale.

Loop / retry logic

  • Inner loop (up to 2 scans): re-scan when the frame-5 check fails (Vtops not above tops_off).
  • Outer loop (up to 2 passes of scan + Adjust Power + Scan_Disable): runs again only when Scan_Disable fails.
Why the rising edge matters HW: on a falling edge, the firmware loop does not hold the lane after the reset. The lane sits at the top of the fringe (about +5 dBm, MPD_OUT ≈ 25), and that gave the "4 dB on CH1" readings seen earlier.
V6.8 vs Python (aligned 2026-10-19: frame 0 order, Peak Search, same-index pairing with its 3 conditions, deepest valley, same-step rule)
  • Sweep step wait: 0.3 s instead of 50 ms (first point 1 s). This station's TXMON refreshes only every ~200 ms, and 50 ms gave stepped curves. It is a config value (mpd_scan.step_settle_s), so 0.05 can be tried for a direct comparison.
  • PY Lane without a valid pair → rescan once; still none → that lane keeps its existing tops_setpoint and tops_off and fails. V6.8 indexes an empty array (zeros), writes 0.2 V to both registers, and the read-back check (Vtops > tops_off) fails.
  • PY Flat curve (peak < max(2 × valley, valley + 50)) → lane kept, logged.
  • PY After the write, tops_lock.relock checks every lane is locked (section 12).
  • The sweep is drawn live in the UI (MPD graph) from mpd_point events.

Search (per lane, all lanes stepped together)

  1. Frame 0: start = present tops_off (the scan's valley). Measure start, start + 0.01, start − 0.01. Direction per lane: up if (start + 0.01) is darker than start, otherwise down. +0.01 and −0.01 are not compared with each other.
  2. Frame 1: 4 steps at (start ± 0.01) ± k · 0.01, k = 1..4, i.e. 2 to 5 steps away from the start. Every step is taken, whatever it reads.
  3. Frame 2: per lane, the voltage with the lowest power of all 7 points (transpose, Array Max & Min, min index: first one on a tie).
  4. Frame 3: write it; disable; wait 0.1 s; read the leakage (this is the Tx_Disable result); enable; wait 1 s.
  5. Frames 4–5: if any lane reads above −18 dBm, every lane takes 5 more steps (k = 5..9), the darkest of all 12 points is written and frame 3 is repeated.

Limit: −60 to −16 dBm. −18 dBm is only the trigger for the extra steps. If a lane fails, the outer Scan_MPD loop runs once more.

HW A tops_off write to a lane that stays disabled has no effect. The lane must go from enabled to disabled, which is why every step disables all lanes and enables them again.
Aligned 2026-10-19. Python now uses the V6.8 step order (write, disable, read, enable, 0.01 s) and its direction rule. It measures the same fixed points (4 steps always taken), picks the darkest of all points, and gives every lane the 5 extra steps. Before, Python compared +0.01 with −0.01, only moved when a step was darker (so it could repeat a point), and stepped only the bright lanes.
V6.8 vs Python
  • Settle before each reading: V6.8 reads straight after the disable (0 s; 0.1 s for the final reading). On this station the leakage needs seconds to settle, so Python polls every 0.5 s (min 1 s, max 8 s). A reading counts once 3 readings agree within 0.5 dB, or the lane is below −22 dBm. The log lists every wait.
  • PY The lanes are re-enabled in a finally block, even on abort or a meter error.
  • PY TOPS relock check after Scan_Disable.
